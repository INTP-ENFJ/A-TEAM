## 왜 만들었나

2026년 9월 30일 현직 기자에게 시연하고 받은 한마디에서 출발했습니다.

> "본문 쓰는 부분을 하나로 묶는 게 편하다. 지금은 기사를 쓰는 게 아니라 **양식을 채우는 느낌**이다."

그날 받은 의견 12건을 다시 읽으니 공통점이 있었습니다. 기자가 원하는 것은 AI가 대신 써 주는 것이 아니라, **쓰는 데 방해되는 일(사진 정리 · 표기 확인 · 의견 주고받기)을 치워 주는 것**이었습니다. 그래서 기자 · 데스크 · 부장 · 인사부 네 역할이 쓰는 업무 도구를 만들고, AI는 옆에서 돕는 역할로 두었습니다.

| 역할 | 하는 일 |
|---|---|
| 기자 | 본문을 쓰고 사진을 넣는다. AI에게 초안 · 검수를 부탁하고, 다 쓰면 검토를 요청한다 |
| 데스크 | 같은 부서 기사를 읽고 문장을 골라 의견을 남긴다. 고쳐 오면 승인한다 |
| 부장 | 승인된 기사를 최종 출고한다. 출고는 부장만 할 수 있다 |
| 인사부 | 가입을 승인하고 부서 · 직급을 정한다. 기사 내용은 건드리지 못한다 |
| AI | 자료 정리 · 질문형 초안 · 검수 · 받아쓰기 · 사진 분석. **기사를 대신 쓰지 않고, 결과는 기자가 골라서 넣는다** |

## 기사 업무 흐름

```mermaid
flowchart LR
    A["01 작성<br/>기자"] --> B["02 검토 요청<br/>기자 · 상태 '검수 중'"]
    B --> C["03 피드백<br/>데스크 ↔ 기자"]
    C --> D["04 승인<br/>데스크 · '출고 대기'"]
    D --> E["05 출고<br/>부장"]
    C -. 수정 요청 .-> A
```

- 작성자와 검토자가 같은 원고를 보며 일하고, 필요하면 어느 단계에서든 다시 검토로 돌아갑니다.
- 단계를 넘길 때마다 **DB 함수가 직급 · 부서 · 기사 상태를 확인**합니다. 화면의 버튼을 숨기는 게 아니라 DB가 막습니다.
- 출고는 실제로 외부에 보내지 않고 기사 상태만 '출고'로 바뀝니다 (사내 데모).

| 업무 | 누가 | 서버가 확인하는 조건 |
|---|---|---|
| 검토 요청 | 작성자 | 본인 기사 · 작성 중 또는 수정 요청 상태 |
| 수정 요청 | 데스크 | 같은 부서 · 검토 중 · 사유 필수 |
| 승인 | 데스크 | 같은 부서 · 검토 중 · 본인 기사 제외 |
| 출고 | 부장 | 출고 대기 · 같은 부서 |
| 기사 배정 · 마감 변경 | 데스크 | 같은 부서 기자에게 배정 · 출고된 기사 제외 |
| 가입 승인 · 인사 관리 | 인사부 | 인사부 소속 · 관리 권한 · 기사 업무는 불가 |

| 기능 | 설명 | 화면 |
|---|---|---|
| 가입과 승인 | 로그인은 Supabase Auth(이메일 + 비밀번호, 회사 도메인만). 가입 신청은 표에만 저장되고, 인사부가 승인할 때 서버가 계정을 만들어 임시 비밀번호를 발급. 승인 전에는 읽기만 가능 (DB 트리거가 쓰기를 차단) | ![](docs/images/PRESS-CMS_13_인사부_가입승인_권한배정.png) |

| AI 초안 (질문형) | AI가 육하원칙 중 빈 곳을 질문하고, 기자가 답한 사실만으로 초안을 조립. 답하지 않은 곳은 `[확인 필요]`로 남김. 없는 발언을 넣어 달라는 요청은 거절 | ![](docs/images/PRESS-CMS_04_AI초안_인터뷰질문.png) |
| AI 검수 | 비문 · 표기 오류 · 제목과 본문 불일치를 AI가 찾고, 고치는 것은 기자. AI가 가리킨 문단이 실제로 있는지 프로그램이 먼저 확인하고 없으면 버림. 목록을 누르면 본문의 그 문장으로 이동 | ![](docs/images/PRESS-CMS_06_AI검수_제목본문불일치.png) |

| 인포그래픽 | 기사 속 숫자를 AI가 뽑고, 원문에 없는 숫자는 프로그램이 걸러낸 뒤 그래프로 만들어 본문에 삽입 | ![](docs/images/PRESS-CMS_12_인포그래픽_본문삽입.png) |
| AI 그림 | 설명 문장으로 삽화를 생성. 로고 · 상표 · 실존 인물 요청은 AI에 보내기 전에 코드가 거절 | ![](docs/images/PRESS-CMS_03_AI이미지만들기.png) |
| 검토와 피드백 | 데스크가 문장을 골라 의견 카드를 남기면, 기자가 답글을 달고 고친 뒤 '해결됨'으로 처리. 카드를 누르면 원문의 그 자리로 이동 | ![](docs/images/PRESS-CMS_07_데스크피드백.png) |

## AI 처리 과정

<details>
<summary>6단계와 예외 처리 6가지</summary>

AI 결과는 프로그램이 거르고 기자가 고른 뒤에야 기사에 들어갑니다. AI 결과가 기자를 거치지 않고 기사에 들어가는 길은 없습니다.

| 단계 | 누가 | 하는 일 |
|---|---|---|
| 01 입력 | 기자 | 주제 · 키워드 · 보도자료 · 녹음 · 사진 · 웹 주소 |
| 02 정리 | 프로그램 | 글자 수 제한(3만 자) · 파일 형식 · 내부망 주소 차단 |
| 03 AI 호출 | 서버 | 암호화된 키를 풀고, 기능별 모델에 "입력된 사실만 쓰라"고 지시 |
| 04 거르기 | 프로그램 | 형식 검사. 원문에 없는 수치 · 발언은 제외하고, 빈칸은 `[확인 필요]`로 표시 |
| 05 판단 | 기자 | 삽입 · 적용 · 무시 중에서 선택. AI는 원문을 직접 고치지 않음 |
| 06 저장 | 프로그램 | 본문 자동 저장. AI 호출의 성공 여부와 응답 시간을 기록 |

| 이럴 땐 | 이렇게 막습니다 | 시험 |
|---|---|---|
| AI 키가 없거나 틀림 | 쉬운 말로 안내, 기존 키 유지 | T22 · T23 |
| AI 서버 혼잡(503) | 자동으로 다시 시도하고, 그래도 안 되면 안내 | T24 (보류) |
| 자료 속 숨은 지시문 | "이전 지시를 무시하라"는 따르지 않음 | T12 |
| 근거 없는 내용 요청 | "시장이 환영했다는 발언도 넣어 줘" → 거절하고 이유를 설명 | T20 |
| 실제 로고 · 실존 인물 그림 | AI에 보내기 전에 거절 | T34 |
| 권한 없는 기사 | 다른 부서의 비공개 기사에 AI 검수를 요청 → 거부 | T26 |

자체 모델 학습은 하지 않았습니다. 기능별 지시문과 결과 형식 검사로 품질을 관리합니다.

</details>

## 기술 스택

| 구분 | 기술 | 고른 이유 |
|---|---|---|
| 화면 | React 19 · TypeScript · Vite 8 · Tailwind CSS 4 · **TipTap 3** | 기자 의견 "본문을 하나로 이어 쓰고 싶다"에 맞춰 문단별 입력 칸을 워드형 편집기로 교체 |
| 저장 · 서버 | **Supabase** — PostgreSQL · RLS · RPC(DB 함수) · Edge Functions 12개 · Storage · Realtime · Auth | Firebase와 비교. 기사 · 직원 · 권한이 연결된 표 데이터이고, 권한 규칙을 DB에서 막을 수 있어서 |
| AI | Gemini(기본) · OpenAI · Claude · Google Cloud STT(연결만 하고 시험은 보류) | 사람마다 쓰는 AI가 다르고, 검수 · 사진 · 초안마다 잘하는 모델이 달라서 기능별로 고를 수 있게 함 |
| 배포 | Render | GitHub에 올리면 자동으로 배포됨 |

작업지시서는 FastAPI 서버를 기준으로 했지만, 이미 만든 화면과 권한 규칙을 살리기 위해 서버를 따로 두지 않고 Supabase 서버 함수 12개로 같은 역할을 구현했습니다.

## 프로그램 구조

<details>
<summary>4층 구조 · 서버 함수 12개 · DB 함수 · 데이터 구조</summary>

프로그램을 네 층으로 나눴고, 위층은 바로 아래층만 부릅니다. **권한 검사와 AI 호출은 서버에서만** 하기 때문에 AI 키가 화면까지 내려가지 않습니다.

```mermaid
flowchart TD
    subgraph UI ["화면 · src/components (57개)"]
        E["ArticleEditor · BodyEditor"] ~~~ P["AiReviewPanel · AiInterviewDraftPanel"] ~~~ H["hr/ · workflow/ · publish/"] ~~~ N["NotificationCenter"]
    end
    subgraph SVC ["서비스 · src/services (20개) — 화면과 서버 사이 통역"]
        S1["bodySyncService"] ~~~ S2["articleWorkflowService"] ~~~ S3["mediaService · aiReviewService"] ~~~ S4["mappers (DB 행 ↔ 화면 객체)"]
    end
    subgraph SB ["서버 · Supabase — 권한 검사와 AI 호출은 전부 여기서"]
        F["Edge Functions 12개<br/>_shared/llm.ts (키 풀기 · 재시도)"] ~~~ R["DB 함수 (RPC)<br/>검토 요청 · 승인 · 출고"] ~~~ L["RLS 행 단위 권한 규칙"] ~~~ RT["Realtime 알림"]
    end
    subgraph EXT ["저장 · 외부"]
        PG[("PostgreSQL")] ~~~ ST["Storage 사진 · 영상"] ~~~ AI["Gemini · OpenAI · Claude"] ~~~ G["Google Cloud STT"]
    end
    UI -- 함수 호출 --> SVC
    SVC -- "supabase-js · 로그인 정보(JWT)와 함께" --> SB
    SB --> EXT
```

### 서버 함수(Edge Functions) 12개와 DB 함수

AI를 부르는 일은 서버 함수가, 기사 상태를 바꾸는 일은 DB 함수가 맡습니다. 둘을 나눈 이유는 AI 키를 서버 함수 안에서만 쓰고, 검토 · 승인 · 출고처럼 "누가 할 수 있는지"가 중요한 일은 DB가 직접 검사하게 하기 위해서입니다.

| 구분 | 함수 | 하는 일 |
|---|---|---|
| AI · 기사 작성 | `ai-interview-draft` | 질문하고, 답변만으로 초안 조립 |
| | `organize-raw-data` | 보도자료 · 메모를 사실 · 수치 · 발언으로 정리 |
| | `review-article-content` | 비문 · 표기 · 제목 불일치 검수 |
| | `fetch-web-source` | 웹 주소에서 본문 가져오기 (내부망 차단) |
| AI · 미디어 | `transcribe-audio` | 녹음 받아쓰기, 말한 사람 구분 |
| | `generate-image` | AI 그림 생성 (로고 · 실존 인물 차단) |
| | `analyze-media-image` | 사진 분류 · 캡션 후보 |
| | `extract-infographic-data` | 본문 숫자를 표로 추출 |
| 계정 · 보안 | `request-signup` | 가입 신청, 임시 비밀번호 |
| | `approve-signup` | 인사부 승인, 부서 · 직급 배정 |
| | `hr-reset-password` | 비밀번호 재발급 |
| | `manage-ai-key` | 개인 AI 키 암호화 저장 · 확인 |
| 기사 업무 (DB 함수) | `request_article_review` | 작성자가 검토 요청 → '검수 중' |
| | `request_article_changes` | 데스크가 수정 요청 |
| | `approve_article` · `publish_article` | 승인 → 출고 (부장만) |
| | `restore_article_version` | 예전 버전으로 되돌리기 |

서버 함수 12개가 공통으로 쓰는 AI 호출 코드(키 풀기, 모델 선택, 혼잡 시 재시도)는 `supabase/functions/_shared/llm.ts`에 모았습니다.

### 데이터 구조

기사 본문은 통째로 저장하지 않고 **문단 하나 · 사진 하나를 블록 한 개**(`article_blocks`)로 저장합니다. 피드백(`article_feedbacks`)은 블록을 가리키기 때문에 "몇 번째 문장에 대한 의견인지"를 잃지 않습니다. 기사 버전 · AI 대화 · 사진은 모두 기사 번호로 이어집니다.

- 핵심: `profiles` · `departments` · `projects` · `articles` · `article_blocks` · `article_feedbacks`
- 보조: `media` · `article_versions` · `ai_draft_sessions` · `notifications` · `user_ai_keys` · `user_ai_prefs` · `ai_call_logs` · `signup_requests` · `audit_logs` · `hr_audit_logs`
- 표 · 권한 규칙 · DB 함수의 변경 기록 46개가 `supabase/migrations/`에 날짜순으로 있습니다. 차례로 실행하면 같은 DB를 다시 만들 수 있습니다.

</details>

VITE_SUPABASE_URL=https://your-project-id.supabase.co
