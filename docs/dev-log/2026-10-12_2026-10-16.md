## 2026-10-12 — AI 검수 보강 및 출고 대기 검토 범위 변경

### 변경한 기능
1. **AI 검수 보강 (`supabase/functions/review-article-content/index.ts`)**: 검수 지침에 아래를 추가.
   - 주어 누락: 앞 문장에서 같은 주체가 이어지는 자연스러운 생략은 지적하지 않고, 주체를 알 수 없을 때만 지적. 사실을 지어내지 않고 불확실하면 `[주체 확인 필요]`로 표시.
   - 제목과 본문의 차이: 제목에만 있는 인물·기관·수치·행위를 제목 구절 기준으로 지적.
   - 영문 표기: 한글 대체어가 분명한 일반 명사는 한글 우선, 널리 알려지지 않은 해외 고유명사는 한글 음차 뒤 영문 병기, 굳어진 약칭(AI, GDP 등)은 지적하지 않음.
   - 해외 대학·기관의 국가명: 첫 언급에 국가가 없으면 국가명을 앞에 붙이도록 권고(예: 미국 하버드대). 국가가 이미 분명하면 지적하지 않고, 알 수 없으면 확인을 안내.
   - 분류 이름(spelling, grammar, title_mismatch, style_guide)은 그대로라서 화면 변경 없음.
2. **표기 가이드 v1.1 (`docs/editorial/PRESS-CMS_기사작성_표기가이드.md`)**: "해외 대학·기관 앞 국가명" 항목 추가.
3. **출고 대기 검토를 부장 이상으로 제한**: `isManagerOrAboveUser`(부장 직급 또는 편집국장 역할) 추가(`types.ts`). 프로젝트 관리의 "출고 대기 검토" 탭(`ProjectDashboard.tsx`)과 업무 대시보드의 출고 대기 카드·목록·건수(`TaskDashboardView.tsx`)가 부장 이상에게만 보임. 사용 가이드와 `docs/부서별_권한_정책.md` 문구 갱신.

### 알려 둘 점
- 출고 대기 제한은 **화면 목록 기준**이며 서버의 접근 규칙은 바꾸지 않음(차장도 서버상 같은 부서 기사 조회 권한은 유지).
- AI 검수 보강은 Supabase에 함수를 다시 올려야(`review-article-content` 재배포) 적용됨.

### 검증 상태
- 리눅스 환경 사본에서 `tsc --noEmit` 오류 0건, `npm run build` 성공.
- AI 검수 결과 확인(주어 누락·영문 표기·국가명 표기 예문)과 부장/차장 계정 화면 확인은 재배포 및 로그인 시험 전.

### 상태
구현 완료 / 재배포·실사용 시험 전

### PPT용 한 줄 요약
> 기자 요청에 따라 AI 검수에 주어 누락·영문 표기·국가명 표기를 추가하고, 출고 대기 검토는 부장 이상에게만 보이도록 좁혔습니다.

## 작업 3. 임시 비밀번호 방식으로 가입·분실 처리 변경 (10-12)

### 배경
- 가입 신청서에 비밀번호 입력이 없고, 승인 시 "초대 메일"이 사내 주소(@pressdesk.co.kr)로 가서 실제로 받을 수 없는 문제를 발견.

### 해결 방식
- 가입 승인 시 인사부 화면에 **임시 비밀번호가 한 번만** 표시됨 → 인사부가 신청자에게 직접 전달.
- 비밀번호 분실 신고도 **[임시 비밀번호 발급]** 버튼으로 같은 방식 처리(본인 확인 후 발급, 기존 비밀번호는 즉시 무효).
- 직원은 로그인 후 **환경설정 > 비밀번호 변경**에서 본인만 아는 비밀번호로 교체(현재 비밀번호 확인, 8자 이상 영문+숫자).
- 임시 비밀번호는 서버에서 무작위로 만들고, 화면에 한 번 보여 준 뒤 어디에도 저장·기록하지 않음.

### 변경 파일

- `src/components/settings/PasswordChangeBox.tsx`(신규), `AccountSettings.tsx`, `auth/LoginView.tsx`(안내 문구), `guide/UserGuideView.tsx`

### 알려 둘 점
- `approve-signup` 재배포와 `hr-reset-password` 새로 배포가 필요함.
- 임시 비밀번호는 인사부가 본인 확인 후 직접 전달하는 방식(메일 자동 발송 없음).

### 검증 상태

## 작업 4. 가입 즉시 임시 비밀번호 + 승인 전 읽기 전용 (10-12)

### 배경
- 인사부가 바로 승인하지 못할 수도 있어, 신청자가 기다리는 동안에도 프로그램을 둘러볼 수 있게 하자는 요청.

### 바뀐 흐름
1. 가입 신청 → 서버가 **승인 대기 계정**을 만들고 **임시 비밀번호를 신청자 화면에 한 번만** 보여 줌(저장·기록하지 않음).
2. 승인 전: 대시보드와 공유된 기사를 **읽기만** 가능. 프로젝트 만들기·이름 변경·삭제·공개 범위 변경·상태 변경·본문 수정·미디어 올리기·피드백 작성·출고는 막힘. 화면 위에 "인사부 승인 대기 중" 안내 표시. 비밀번호 변경은 가능.
3. 승인(인사부): 배정한 부서·직책·직급·역할이 계정에 반영되고 모든 기능이 열림. 승인되면 대기 화면이 30초 안에 자동으로 풀림.
4. 반려: 계정이 사용 중지되어 로그인 불가.
- 승인 대기 표식은 본인이 바꿀 수 없는 서버 영역(`app_metadata.approval`)에 저장.
- 직급·역할은 신청자가 정할 수 없고 항상 기본값(기자)으로 만들어짐.

### 변경 파일
- `supabase/functions/request-signup/index.ts`(신규, 로그인 전 호출), `supabase/functions/approve-signup/index.ts`
- `src/components/auth/LoginView.tsx`, `src/components/hr/SignupApprovalTab.tsx`, `src/App.tsx`, `src/types.ts`, `src/components/dashboard/ProjectDashboard.tsx`, `src/components/editor/ArticleEditor.tsx`, `guide/UserGuideView.tsx`

### 알려 둘 점
- 읽기 전용은 **화면 기준**입니다(서버 데이터 규칙은 그대로). 일반 사용자가 개발자 도구로 직접 서버를 호출하는 경우까지 막지는 못합니다.
- 누구나 아이디를 먼저 신청해 선점할 수 있으므로, 승인 전에 이름·아이디를 확인하고 의심되면 반려해야 합니다.
- `request-signup`은 로그인 전에 호출되므로 `--no-verify-jwt`로 배포 필요.
