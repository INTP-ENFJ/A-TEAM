# PRESS-CMS 발표 자료(HTML) 구성안 — 아이디어 단계

> 2026-10-12 작성. 아직 제작 전이며, 내용은 주간 개발 기록(DEV_LOG)과 1차 발표 자료(PDF 24쪽)를 바탕으로 한 제안입니다.

## 1. 왜 HTML인가
- 움직이는 화면(영상)을 넣어도 PPT처럼 파일이 무겁거나 깨지지 않습니다. GIF 대신 mp4/webm 영상을 쓰면 용량이 훨씬 작습니다.
- 실제 코드를 색깔 입혀 보여 주고, 같은 화면에서 영상이나 작은 시연(드래그 앤 드롭 등)을 바로 틀 수 있습니다.
- 제출용으로는 PDF로도 뽑을 수 있습니다(인쇄 기능).
- 주의: 영상 파일은 HTML 옆 폴더에 따로 두므로 **폴더째** 옮겨야 하고, 발표장에 인터넷이 없을 수 있어 글꼴·코드 색 표시 도구까지 모두 폴더에 넣습니다.

## 2. 목차 (제작 순서 = 발표 순서, 약 32장)
**0. 시작**
- 0-1 표지 · 0-2 목차

**1. 프로젝트 소개** (1차 자료를 3장으로 압축)
- 1-1 문제 상황 · 1-2 PRESS-CMS 한 줄 소개와 작성→검토→협업→출고 흐름 · 1-3 프로그램 구성(화면·서버·저장)

**2. 화면 둘러보기 (탭별 소개)** — 탭마다 영상 10~20초 + 한 줄 설명
- 2-1 로그인·가입 신청 · 2-2 대시보드(업무 / 프로젝트 / 출고 대기 검토) · 2-3 기사 편집기(워드형 본문, 사진 이동·자르기·가리기)
- 2-4 의견(피드백) · 2-5 AI 도구(AI 검수, AI 인터뷰 초안, 인포그래픽) · 2-6 출고
- 2-7 미디어 라이브러리(사진·영상 정보 자동 입력) · 2-8 이력(버전 기록·업무 이력) · 2-9 알림 · 2-10 설정과 사용 가이드
- 2-11 인사부(직원 명부, 가입 승인, 비밀번호 분실, 부서·직책, 변경 기록)

**3. 핵심 기술 들여다보기** — 실제 코드 + 움직이는 화면 + 일반인용 한 줄
- 3-1 드래그 앤 드롭(사진 끌기, 파란 안내선) · 3-2 한 번에 처리되는 저장(글 중간 사진 삽입)
- 3-3 Supabase 연결과 권한 규칙 · 3-4 실시간 알림 · 3-5 AI 초안과 근거 표시(초록/노랑)

**4. 문제를 만나고 해결한 과정**
- 4-1 대표 사례 4건 상세(수정 전/후 코드 비교) · 4-2 나머지 6건 요약 카드 · 4-3 배운 점

**5. 현장 목소리**
- 5-1 받은 피드백과 반영 현황 표 · 5-2 기자 인터뷰(강사님) · 5-3 기자 인터뷰(팀 준비)

**6. 앞으로**
- 6-1 직업 관련 기술(영상·이미지) · 6-2 AI 검수 강화와 배포 계획 · 6-3 팀과 역할 분담 · 6-4 마무리

**조작 방식**: 키보드 ← → 로 넘기기, 왼쪽 목차에서 바로 이동, 전체 화면, 영상 재생/멈춤, 코드 접기/펼치기, 인쇄하면 PDF 백업본.

## 3. 핵심 코드 시연 후보 (실제 파일 기준)
| 주제 | 보여줄 것 | 실제 코드 위치 |
|---|---|---|
| 드래그 앤 드롭 | 사진을 끌어서 본문 문단 사이·글자 중간에 놓기, 파란 안내선, 놓는 즉시 저장 | `BodyEditor.tsx`, `bodySyncService.ts`, DB 함수 `split_article_text_and_insert_media`, `insert_article_media_block` |
| Supabase 연결 | 화면이 Supabase에 접속하는 단 몇 줄, 권한 규칙(RLS), 함수 호출(RPC) | `lib/supabase.ts`, `articleService.ts`, 마이그레이션 SQL |
| 실시간 알림 | 한쪽에서 의견을 달면 다른 쪽 화면에 바로 알림 | `NotificationCenter.tsx`(Realtime 구독), 알림 트리거 SQL |
| AI 인터뷰 초안 | 질문·답변이 오가며 기사가 조립되는 화면, 서버 함수 호출 | `AiInterviewDraftPanel.tsx`, `supabase/functions/ai-interview-draft` |
| AI 근거 표시 | 근거 있는 문장 초록, 없는 문장 노랑 | `evidenceCheck.ts` |
| AI 검수 | 맞춤법·비문·제목-본문 불일치·표기 규칙 | `review-article-content` |
| 권한 | 같은 부서 데스크만 검토, 최종 출고는 부장, 인사부는 기사 업무 불가 | `docs/부서별_권한_정책.md` |

화면 구성 방식: 왼쪽에 실제 코드(핵심 10~15줄만 발췌), 오른쪽에 같은 기능의 움직이는 화면, 아래에 일반인용 한 줄 설명.
공개 전 점검: 키·비밀번호·`.env` 내용이 코드 조각이나 화면에 보이지 않게 하고, 실제 사람 이름·이메일은 시험 계정만 사용합니다.

## 4. 버그와 해결 사례 후보 (DEV_LOG에서 선별)
| # | 증상(쉬운 말) | 원인 | 해결 |
|---|---|---|---|
| 1 | 사진 저장이 권한 거부로 막힘 | 보안 규칙이 파일 경로 대신 프로젝트 이름을 검사(이름이 겹쳐 잘못 연결됨) | 보안은 그대로 두고 경로를 정확히 지정 |
| 2 | 새 프로젝트가 안 만들어짐 | 화면이 보낸 항목 이름이 서버가 받는 이름과 다름 | 서버는 그대로, 화면의 보내는 값만 맞춤 |
| 3 | 사진을 올리기 전에 멈춤 | 일부 브라우저에서 고유번호 생성 기능이 없음 | 안전한 대체 방법 추가 |
| 4 | 출고 대기 기사가 부장 목록에 안 보임 | 본인 기사 제외 조건과 첫 기사만 보던 구조 | 조건 제거, 출고 대기 기사를 우선 표시 |
| 5 | 상태 비교가 항상 틀림 | 'Ready'와 'ready'(대소문자) 불일치 | 비교 값을 하나로 통일 |
| 6 | 사진을 옮기면 새 사진으로 오인 | 두 종류의 끌기 정보가 같은 통로를 씀 | 하나의 규격으로 통일 |
| 7 | 글자 중간에 사진을 넣으면 글이 사라짐 | 글 나누기와 사진 넣기가 서로 덮어씀 | 서버에서 한 번에 처리(중간 상태 없음) |
| 8 | 알림이 오지 않음 | 옛 버전 SQL이 실행됨 | 수정본 재실행 후 확인 |
| 9 | 목록 조회 400 오류 | 관계 이름이 서버와 안 맞음 | 이름 결합을 없애고 따로 조회 |
| 10 | 다른 창에 다녀오면 화면 깜빡임 | 복귀 때 같은 로그인 신호를 다시 처리 | 이미 같은 사용자면 무시 |

(대표 사례 3~4건은 코드 비교 화면(수정 전/후)으로, 나머지는 카드로 소개)

## 5. 피드백·인터뷰·직업 관련 기술
- 피드백: 9/30 의견, 10/8 의견, 1차 발표 의견을 "받은 말 → 우리가 한 일 → 상태" 표로 정리 (`2026-10-12_2026-10-16.md` 표 활용).
- 기자 인터뷰: 강사님 인터뷰와 팀 인터뷰 자리를 따로 마련 (자료 도착 후 채움).
- 직업 관련 기술(영상·이미지): 지금 구현된 것(사진 가리기, 자르기·확대, 인포그래픽, AI 이미지 생성·분석, 녹음 받아쓰기)과 앞으로 할 것(영상 관련)을 나눠 보여 주는 슬라이드 제안.
- 역할 분담: "코딩을 아예 안 하는지" 질문에 대한 팀의 답을 정해 한 장으로 정리 (팀 결정 필요).

## 6. 화면 모양(테마): 프로그램과 똑같이
발표 HTML은 프로그램의 `src/index.css`에 있는 색과 글꼴을 그대로 가져와 쓰고, 별도 초록색 계열은 쓰지 않습니다.
| 요소 | 프로그램 값 |
|---|---|
| 왼쪽 메뉴·어두운 영역 | 짙은 남색 그라데이션 `#152a44 → #0d1c30` |
| 상단 띠 | `#16304f → #3b6ea5` |
| 강조·버튼 | 파랑 `#3b6ea5 → #1e3a5f`, 선택 상태 `#4a86c2 → #1e3a5f` |
| 바탕·글자 | 연한 회청 `#f8fafc`, 글자 `#0f172a`, 회색 계열은 slate |
| 보조 색 | 데스크·출고 대기 보라, 확인 필요 주황(amber), 근거 있음 초록(emerald), 오류 장미(rose) |
| 글꼴 | 본문 Noto Sans KR, 기사 본문 Noto Serif KR, 코드 JetBrains Mono (프로그램과 동일) |
| 드래그 표시 | 파란 선 `#2563eb`, "여기에 놓입니다" 배지 |
| 모양 | 둥근 모서리, 가는 테두리, 약한 그림자(프로그램 카드와 동일) |
프로그램 색이 바뀌면 같은 값을 다시 가져올 수 있도록 색을 한곳(변수)에 모아 둡니다. 어두운 영역(표지·코드 화면)은 프로그램의 사이드바 색을 씁니다.
