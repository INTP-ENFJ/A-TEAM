# PRESS-CMS 부서별 권한 정책 (현재 서버가 실제로 지키는 규칙)

기준일: 2026-10-08. 아래는 화면이 아니라 **서버(Supabase)에서 강제하는 규칙**입니다. 화면에서 버튼을 숨기는 것과 별개로, 규칙을 어기면 서버가 거절합니다.

## 1. 누가 "데스크"인가
- 직급이 **부장·차장**이거나, 역할이 **데스크 에디터·편집국장**이면 데스크입니다.
- **인사부 관리자**(인사부 소속 + 가입 승인 권한)는 기사 업무를 전혀 할 수 없습니다. (검토 요청, 수정 요청, 승인, 배정 모두 거절)

## 2. 기사 업무별 규칙
| 업무 | 할 수 있는 사람 | 추가 조건 |
|---|---|---|
| 검토 요청 | 기사 작성자 본인 | 상태가 "작성중" 또는 "수정요청"일 때만 |
| 수정 요청 | 데스크 | **같은 부서** 기사만, 상태가 "검토중"일 때만, 사유 필수 |
| 승인(출고 대기로) | 데스크 | **같은 부서** 기사만, 상태가 "검토중"일 때만, **본인이 쓴 기사는 승인 불가** |
| 최종 출고 | 부장 | 출고 대기 상태의 기사 |
| 기사 배정·마감 변경 | 데스크 | 같은 부서 기자에게만 배정, 출고 완료 기사는 변경 불가 |

## 3. 알림이 가는 사람
- 검토 요청 → **작성자와 같은 부서의 데스크 전원**
- 수정 요청·승인·출고 → 기사 작성자
- 새 피드백 → 기사 작성자
- 배정·마감 변경 → 담당 기자

## 4. 기사 공개 범위
- 기사는 "미공개 / 같은 부서 / 전체" 중에서 고릅니다.
- "출고 대기" 상태의 기사는 공개 범위와 상관없이 같은 부서 데스크가 검토할 수 있습니다.

## 5. 팀이 정해야 할 것 (아직 규칙이 없는 부분)
1. 다른 부서 데스크가 급할 때 대신 승인해도 되는지 (지금은 불가)
2. 차장이 최종 출고까지 할 수 있는지 (지금은 부장만)
3. 편집국장이 모든 부서 기사를 볼 수 있어야 하는지 (지금은 같은 부서만)
